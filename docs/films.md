# Films

The rules for the code that makes films: the film renderer, scripts, reels, shapes and captions, the encoder, the particle crew and the `space` MCP server. `CLAUDE.md` holds the rules for the scene a film draws, and the words *gated* and *deterministic* used here. Fractal films reuse the readers, captions, caption text and script engine described here, and a reel plays fractal clips; their own rules are in `docs/fractal_films.md`.

A film is the scene as a 1-180 s mp4, described by one JSON object: frame and length, seed, starting settings, the intro as a clip, keyframes for any numeric setting or intro parameter, captions. The format is written once, as `FILM_GUIDE` in `src/lib/film.ts`, and the script that is a shorter way to write it as `SCRIPT_GUIDE` in `src/lib/film_script.ts`; `window.space.film.guide()` and the `space_guide` tool both return the two, so change the guide when the format or the language changes.

- **The `space` MCP server** (`mcp/space_mcp.mjs`, in `.mcp.json`) is how an agent makes one: `space_guide`, `space_describe`, `space_check` (the film read back as a timeline, without drawing), `space_preview` (a contact sheet of frames; the storyboard of a film cut into shots) and `space_render` (the mp4, with an optional audio file under it). Each takes a film as its JSON (`film`) or as a script (`script`, with `input`). It serves `dist/` from this machine and keeps one headless Chrome on it, so run `pnpm build` after changing the page. It has no dependencies: JSON-RPC lines on stdio, the browser over its DevTools socket. The page does the work through `window.space.film` (`check`, `preview`, `render`, `progress`, `cancel`), which also works from the console of any page with `?agent`.
- **A film plays in a scene of its own** (`src/lib/film_render.ts`): a second `createScene` on a canvas of the film's size, stepped by a fixed `dt` with no clock, so the page's scene and its saved settings are never touched and a slow machine draws the same frames as a fast one. It starts from the page's defaults, never from this browser's settings. Motion is stepped at about 60 Hz for a film of up to 60 fps (`frame.present` is false for the steps between two frames) and once a frame above that, up to 240 fps: the same motion at any rate, though not the same frames. The tracks move at every step, each at its own second, so a fast one (a turning camera) streaks as it does live. The same seed gives the same frames; a preview frame is the frame the render makes.
- **A film plays live in the film mode** (`src/lib/film_live.ts`, driven by `film_session.ts` and `film_mode.tsx`): the players a render draws with (`createFilmPlayer`, `createFractalPlayer`, `createReelPlayer`) draw it at the screen's size, paced by the clock, so every frame shown is the frame the render makes. A frame there is no time for is stepped without being shown, and a film that falls further behind slows down rather than skip ahead. A scene only goes forward, so playing again from the end makes a new player. A film that loads there is checked by the same planners, renders through the same `renderFilm`, `renderFractal` and `renderReel`, and finds the files it names (a reel's clips, a shape's picture) among the files given beside it and then in `films/`, which `film_library.ts` bundles as lazy chunks. A new kind of film plays live once `loadFilm` and `makePlayer` know it.
- **`planFilm` checks a film against the same registries as `window.space`** (`src/lib/agent_values.ts`): a new simulation setting or intro parameter is settable and animatable in films as soon as it is in its spec (a setting that is neither a slider nor a colour needs the two lines `CLAUDE.md` names). On a track a switch flips at its key's second (`TRACK_SWITCHES`); a colour setting (`COLORS`) is keyed as `'#rrggbb'`, moves as a number channel by channel like the opening's colours, and `applyTracks` writes it back as the text the store keeps; the palette is set and never moved. Read each part of a film through `attempt`, which keeps the problem and reads on, so a film with several mistakes is told all of them at once. What a film asks for and will not get is a note, not silence (the opening's film look without `filmHold`, a face without the words' letters).
- **A film is a timeline, and each ability of the scene is one kind of thing on it**: a value moves along keyframes (`tracks`), a layer switches (`layers`), the intro is a clip (`intro`), an event of the intro is fired again (`cues`), and the scene's own time slows or stops (`speed`). What the intro debugger does with time and layers, a film does, and the audit holds that. A layer is declared once in `src/lib/intro_tracks.ts`: its line in `INTRO_LAYER_NOTES`, and its place in `CUE_LAYERS` if it is an event; `describe`, the guide and the checks read that. `scene.fire` plays events on three clocks kept with the scene (the blast, the ringing, a title), sampling the intro's own timeline into a second frame and laying it over the first, so a fired event is drawn by the code that draws the opening and is gated by whether one plays. A fired title's own words are drawn before the first frame (`scene.makeTitle`) and put in place at the cue (`scene.useTitle`), since a film cannot wait for a face in the middle. What the words are drawn from (their size, widest line, line spacing, weight, tracking and the halo's reach and streak: `TITLE_DRAWN_KEYS` in `intro_params.ts`) is read then and only then, by `titleStyle` in `film_render.ts` and `readTitleStyle` on the page: a new parameter of the title's sprite goes into the list and into both, and `planFilm` tells a film whose track is on one that it moves nothing. The opening's film look (letterbox, vignette, grain, fringe) leaves with the opening; the intro parameter `filmHold` is the share of it that stays. `speed` bends the scene's step, never the film's seconds: the intro's start is worked out in scene time from it (`introTime`), and slow motion takes finer steps. `planFilm` returns the film as it understood it (`timeline`), which `check` and every preview show.
- **A film written as a script is the same JSON, said shorter** (`src/lib/film_script.ts`): JavaScript that plays the film forward on a cursor of time (`wait`, `to`, `drive`, `shot`, `caption`, `fire`, `meanwhile`), so no second is written by hand, a part of a film is a function and the film is as long as what was played. `writeFilm` runs the text in the page and returns the film object `planFilm` takes; `check`, `preview` and `render` take a string as a script. Nothing reaches the renderer but through that JSON, so a new ability goes into the film format first and then gets its word. The words are `SCRIPT_WORDS`, each told in `SCRIPT_GUIDE`. A value's moves are gathered and written as keys when the script ends (`writeKeys`): a film's own ease is one key, a spring or a function is 60 linear keys a second (`BAKE_RATE`), and two moves of one value at once are refused with both lines. A script's chance comes from the film's seed, `Math.random` included, so the same script is the same film. A mistake names its line, found on the stack through the script's `sourceURL`; a mistake of grammar gets its line in the MCP server (`vm.Script`, which reads and never runs), because the page's engine does not say it. The audit holds that the guide tells every word and its example runs, that a script and the JSON it stands for give the same plan, that a script moves everything a film moves, and that the lines are named.
- **Two things of a film are not the scene's**: `fade`, a share of black laid over the finished frame and under the captions (`filmFade`, drawn in `film_render.ts`), and `shots`, names for stretches of the film that change no frame and make a preview a storyboard, one frame from the middle of each.
- **A reel is several films in one video, and draws nothing itself** (`src/lib/reel.ts`, `src/lib/reel_render.ts`): a description with `clips` is a reel, taken by the same commands and tools as a film. It is a third player beside the film's and the fractal's: for a frame it has the clip's own player draw that clip's frame and copies it to one canvas (two players during a dissolve, the second laid over with its share; black is a fill), and hands that canvas to the same `encodeVideo`. A clip in a reel draws the frames it draws alone, the same seed and the same steps. A kind of clip is one entry in `CLIP_READERS` (read and plan) and one in `CLIP_PLAYERS` (make its player), and the audit fails until it has a film to plan. A player is made when its first frame is near and disposed after its last, so only a dissolve holds two scenes; one that cannot get its second scene is played through black with a note. A clip given as a path is read by the film server, never by the page.
- **Shapes are drawn over the finished frame too** (`graphics`, `src/lib/film_graphics.ts`): over `fade`, under the captions, on the same 2D canvas, and never in the scene. A kind is declared once in `film.ts` (`GRAPHIC_KINDS`, its keys in `GRAPHIC_KEYS`, read by `readGraphics`), and the audit holds that each plans with every key and that the guide tells it. A place on the scene (`{ hole: [dx, dy] }`, in a shape or as a caption's `at`) is put on the frame by `holeOnFrame` and `placeOnFrame` in `film_captions.ts`, the one home of that sum, which reads the camera from the frame's composite settings; a number given by name is read as a caption's `#{key}` is. Pictures are decoded before the first frame; the film server hands a path on its machine to the page under a one-off token, as it does a sound file. A film with no shapes never calls into that module.
- **Captions are drawn over the finished frame** on a 2D canvas (`src/lib/film_captions.ts`), never in the scene: the page has no captions. A line wider than the frame is broken at its spaces (`fitCaption`, worked out once for a caption), and words in a face that lacks their letters go to the bundled face that has them (`faceFor` in `film.ts`: of the display faces Cyrillic is in Unbounded alone), because a fallback to the machine's own face would make the same film a different video elsewhere.
- **A caption's text is what popular science is written in** (`src/lib/caption_text.ts`, read once by `planFilm`): a mark is a sign with a brace right after it, so plain text with an underscore or an asterisk of its own is never read as one (`_{s}` lowered, `^{2}` raised, `*{term}` in the accent colour, `#{key:1}` a number read from the film at that second: the caption's own `values`, the film's `seconds`, or any number of the scene after the tracks). Behind every bundled face stand Noto Sans, Noto Sans Math and Noto Sans Symbols (`public/fonts`, declared in `index.css` each with only the characters the faces before it lack, so a caption loads no file it will not use and the page none at all), which hold Greek, mathematics and the signs of the Sun and the planets; `COVERED` in `caption_text.ts` is every character those files hold, read from their character maps, and is what the note about the machine's own face goes by, so a new font file means a new `COVERED`. A line with no marks that is all there is drawn as one string; a line with marks, a caption that arrives a letter, a word or a line at a time (`reveal`), and one with `align` are drawn piece by piece from one layout (`layOut`). A caption with a live number is laid out again when its words change and keeps the block of its widest number (`steady`), so nothing shakes as digits change.
- **A film is encoded by WebCodecs** through `mediabunny`, imported only when a film is rendered, so visitors never download it. The bitrate is counted for 60 fps at most (`BITRATE_FPS`), and a stream above the level the browser's encoder names gets the true one written into the decoder's description (`raiseAvcLevel`); the reasons are at both, and what was measured and found of no use for speed is above `encodeVideo`.
- **A render through the MCP server is never held in the page.** The file is sent as it is encoded, a piece at a time with the place the piece belongs at (`upload`, `at`), and the server writes each piece in place; room for the index is kept at the start of the file (`fastStart: 'reserve'`, which needs the count of packets of every track), so the file plays before it is all there and its size is not bound by the tab's memory. Only a film saved by hand with `download` is put together in the page.
- **A film's particles are stepped on several cores, deterministically: the bytes of the plain loop** (`src/lib/particle_crew.ts`). `stepParticles` is `stepRange` over the whole field; a crew cuts the field into pieces that the main thread and up to seven workers step with that same loop (`particle_pieces.ts`). What reaches beyond one particle is written down and played back on the main thread in particle order (`StepLater`, `settleLater`; the rule for the hot loop is in `CLAUDE.md`). The pieces' segments are not packed together, because copying within shared memory cost as much as the step itself; the renderer uploads the runs in order (`instanceRuns`). A crew needs memory shared between threads, which a page gets only with the two isolation headers the film server sends; on the deployed page and the dev server a film is stepped by the plain loop.

## Verify

A film change is done when each check that applies passes:

- Two previews with one seed are the same bytes, and a rendered mp4 plays (`<video>` in Chrome, or mediabunny's `Input` in Node for its tracks).
- Films that do not use the change keep their bytes, or the difference is meant and shown with a frame before and after (`SPACE_DIST` points `space.mjs` at the build before the change).
- A change to the step: a preview is the same bytes from the film server, which steps with the crew, and with `SPACE_PLAIN=1`, which leaves out the isolation headers so the plain loop steps it.
- A change to reels: a reel of one clip previews to the film's own bytes.
- A change to what fractal films share (`film_render.ts`, `readPace`, `readCaptions`, `readShots`, the captions, the caption text, `playScript`): particle and fractal films keep their bytes or change as meant, and a fractal film still renders.
